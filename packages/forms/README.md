# 신청 폼 (forms)

해커톤 참가 신청을 받는 웹 페이지와 그 백엔드입니다. [ENDPoinT 2026](https://2026endpoint.github.io) 사이트의 **참가 신청 화면을 디자인 그대로** 떼어 내고, 대회마다 바뀌는 글과 질문만 설정으로 뺐습니다. 첫 화면·동아리 소개·팀 게시판·운영진 페이지는 없고, 신청 화면 한 장입니다.

- **사이트** (`site/`): 정적 HTML·CSS·JS. 빌드 없이 GitHub Pages에 올립니다.
- **백엔드** (`apps-script/`): 구글 시트에 붙은 Google Apps Script 웹 앱. 답을 검사해 시트에 한 사람 한 줄로 씁니다.
- **GitHub 아이디**를 기본 질문으로 받습니다. 형식이 틀리면 브라우저와 서버 양쪽에서 막고, 입력하는 동안 `github.com/아이디` 링크를 보여 줘 본인 계정이 맞는지 확인하게 합니다.
- 시트의 열 이름(`이메일`, `성함`, `GitHub 아이디`)은 [MCP 서버](../mcp)의 기본 설정과 같아서, MCP가 이 시트를 바로 명단으로 읽습니다.

## 어디를 고치나

| 파일 | 고치는 것 |
| --- | --- |
| [`apps-script/Config.gs`](apps-script/Config.gs) | **질문**, **모집 기간**, 응답 탭 이름, 로그인 안내·개인정보 한 줄. 사이트는 이 질문을 서버에서 받아 그리므로 질문은 이 한 곳에만 있습니다. 서버도 같은 기준으로 매 제출을 검사합니다. |
| [`site/config.js`](site/config.js) | 로그인 클라이언트 ID·서버 주소, 대회 이름(로고), 탭 제목, 헤더 메뉴, 페이지 머리(제목·세 칸), **신청 과정**, **유의사항**, 제출 후 화면, 약관·개인정보처리방침 링크, 푸터 |
| [`site/assets/theme.css`](site/assets/theme.css) | 색·글꼴 (맨 위 `:root` 변수). 나머지는 ENDPoinT 스타일 그대로입니다. |

`config.js`의 글에는 줄바꿈(`\n`), `**굵게**`, `[글자](주소)`를 쓸 수 있고, `{period}`(10.07 – 10.31)·`{open}`·`{close}`는 `Config.gs`의 모집 기간으로 바뀝니다. 그래서 날짜는 `Config.gs`에만 적으면 됩니다.

```
site/
├── index.html        화면 뼈대 (헤더 · 페이지 머리 · 신청 과정 · 유의사항 · 신청서 · 푸터)
├── config.js         대회마다 고치는 글
├── demo-form.js      미리보기용 질문 (Config.gs 기본값과 같음, 테스트가 확인)
└── assets/
    ├── theme.css     ENDPoinT 테마
    └── app.js        로그인 · 모집 기간 · 신청서 (ENDPoinT 신청 스크립트를 옮긴 것)
```

## 안전장치

| 장치 | 내용 |
| --- | --- |
| 로그인 확인 | 구글 로그인 ID 토큰을 요청마다 구글에 확인합니다(이 사이트용인지, 이메일 인증, 만료). 이메일은 폼 입력이 아니라 토큰에서 가져옵니다. |
| 모집 기간 | 페이지뿐 아니라 **서버가 매 제출마다** 확인합니다. 주소를 알아도 기간 밖에는 저장되지 않습니다. 열어 둔 탭은 마감 시각이 되면 새로 고쳐져 마감 화면이 됩니다. |
| 입력 검사 | 필수, 길이, 보기 목록, 전화번호, GitHub 아이디 형식을 서버가 다시 검사합니다. 설정에 없는 항목은 버려서 참가자가 열을 늘릴 수 없습니다. 서버가 막은 항목은 화면에서 그 칸을 짚어 줍니다. |
| 시트 보호 | 모든 칸을 텍스트로 쓰고 앞의 `=`를 지워 수식으로 실행되지 않습니다. |
| 중복 방지 | 응답이 끊겨 다시 보낸 제출은 한 번만 처리하고(nonce), 동시 제출은 잠금으로 줄 세웁니다. 응답을 끝내 못 받으면 시트에 같은 내용이 들어갔는지 확인한 뒤 알려 줍니다. |
| 화면 | 서버·설정·참가자 글자는 모두 이스케이프하거나 `textContent`로 넣습니다. 링크는 `http(s)`·`mailto`·사이트 안 주소만 만듭니다(`javascript:` 등은 링크가 되지 않음). |
| 공용 PC | 작성 중인 내용은 이 브라우저에만 임시 저장되고, 제출하거나 로그아웃하면 지워집니다. 다른 계정의 임시 저장본은 쓰지 않습니다. |
| 권한 최소 | 스크립트는 붙어 있는 시트 하나(`spreadsheets.currentonly`)와 토큰 확인용 외부 요청만 씁니다. |

## 설치

1. **시트와 스크립트**: 응답을 받을 구글 시트를 만들고 *확장 프로그램 → Apps Script*를 엽니다. `Code.gs`, `Config.gs`를 붙여 넣고, *프로젝트 설정 → "appsscript.json 표시"*를 켠 뒤 [`appsscript.json`](apps-script/appsscript.json)도 그대로 붙여 넣습니다. ([clasp](https://github.com/google/clasp)로 `apps-script/`를 그대로 올려도 됩니다.)
2. **질문 고치기**: `Config.gs`의 `GATE`(모집 시작·마감), `FORM`(질문), `EVENT`(로그인 안내·개인정보 한 줄)를 대회에 맞게 고칩니다.
3. **로그인 클라이언트**: [Google Cloud 콘솔](https://console.cloud.google.com) → *Google Auth 플랫폼 → 클라이언트 → 웹 애플리케이션*. *승인된 JavaScript 원본*에 사이트 주소(예: `https://your-org.github.io`)와 로컬 확인용 `http://localhost:8000`을 넣습니다. 범위는 기본(`openid email profile`)만 쓰므로 앱 심사가 필요 없습니다. *대상*을 프로덕션으로 바꿔야 테스트 사용자 100명 제한이 풀립니다.
4. **스크립트 속성**: *프로젝트 설정 → 스크립트 속성*에 `CLIENT_ID`(3번의 클라이언트 ID)를 넣습니다. 특정 학교 계정만 받으려면 `ALLOWED_DOMAIN`(예: `example.ac.kr`)도 넣습니다.
5. **준비 실행**: 편집기에서 `setup`을 한 번 실행해 권한을 승인합니다. 응답 탭과 머리글 행이 만들어집니다.
6. **배포**: *배포 → 새 배포 → 웹 앱*, 실행 사용자 *나*, 액세스 *모든 사용자*. 나온 `/exec` 주소를 복사합니다. 코드를 고치면 *배포 관리 → 새 버전*으로 다시 배포해야 반영됩니다.
7. **사이트**: [`site/config.js`](site/config.js)에 `CLIENT_ID`와 `ENDPOINT`(6번 주소)를 넣고, 대회 이름·신청 과정·유의사항·푸터를 고친 뒤 `site/` 폴더를 GitHub Pages로 올립니다. 탭 아이콘과 링크 미리보기 이미지는 `index.html` 머리의 주석 자리에 넣습니다.
8. **확인**: 사이트에서 로그인 → 제출 → 시트에 한 줄이 생기는지 봅니다. 같은 계정으로 다시 들어오면 제출한 내용이 읽기 전용으로 열리고, *수정하기*로 고칠 수 있습니다.

다른 시트에 쓰려면(스크립트를 시트에 붙이지 않을 때) 스크립트 속성 `SHEET_ID`를 넣고, `appsscript.json`의 `spreadsheets.currentonly`를 `spreadsheets`로 바꿉니다.

## 미리보기

`config.js`의 `CLIENT_ID`나 `ENDPOINT`가 비어 있으면 **데모 모드**로 열립니다. 아무 데도 보내지 않고, `demo-form.js`의 질문으로 화면과 검사를 확인할 수 있습니다(제출 내용은 개발자 도구 콘솔에 찍힘).

```bash
cd packages/forms/site && python -m http.server 8000   # http://localhost:8000
```

로컬(`localhost`·`127.0.0.1`·`file://`·사설 IP)과 데모 모드에서는 날짜와 상관없이 신청서가 열립니다. 닫힌 모습은 주소 끝에 붙여 봅니다. 배포된 사이트에서는 이 주소가 무시됩니다.

| 주소 | 화면 |
| --- | --- |
| `?gate=closed` | 모집 전 (신청 버튼이 "10.07 오픈" 라벨로, 신청서 자리에 안내) |
| `?gate=after` | 마감 후 |
| `?gate=real` | 서버가 판정한 실제 상태 |

## 질문 형식

`Config.gs`의 `FORM`은 섹션 목록입니다. 섹션 하나가 화면에서 접히는 한 줄(01, 02, …)이 됩니다.

| 섹션 키 | 내용 |
| --- | --- |
| `name` | 줄 제목 |
| `hint` | 펼쳤을 때 위에 보이는 안내. `\n`은 줄바꿈, 주소는 링크가 됩니다 |
| `optional` | `true`면 제목에 `*`가 붙지 않습니다 |
| `summary` | 비어 있을 때 줄 오른쪽에 보이는 회색 글자. 없으면 질문 이름이나 "중복 선택 가능" |
| `fields` | 질문 목록. 둘 이상이면 두 칸 격자로 놓입니다 |

| type | 화면 | 서버 검사 |
| --- | --- | --- |
| `text` | 한 줄 입력. `chips`가 있으면 누르면 붙는 빠른 입력 버튼 | 길이(기본 200) |
| `tel` | 전화번호 | 숫자·`+-()`·공백 7~20자 |
| `textarea` | 여러 줄 | 길이(기본 2000) |
| `single` | 하나만 고르는 버튼 | `options` 안에 있는지 |
| `multi` | 여러 개 고르는 버튼. `solo`의 보기는 고르면 나머지가 풀림(예: "없음") | 보기 안인지, `solo`와 함께 골랐는지 |
| `github` | GitHub 아이디. `@아이디`·프로필 주소도 받아 아이디만 저장, 프로필 링크로 확인 | GitHub 아이디 규칙 |

공통: `key`(시트 열 이름이자 화면 라벨), `required`, `placeholder`, `max`, `full`(두 칸 차지). `제출시각`, `이메일`, `계정 식별자`는 서버가 채우는 열이라 `key`로 쓸 수 없습니다.

## MCP와 연결

[MCP 서버](../mcp)의 `event.yaml`에서 명단을 이 시트로 지정하면 됩니다.

```yaml
roster:
  source: google_sheets
  spreadsheet: "https://docs.google.com/spreadsheets/d/<이 시트>/edit"
  participants_tab: 웹신청          # Config.gs 의 SHEET.name
  columns: { email: 이메일, name: 성함, google_sub: 계정 식별자, github_login: GitHub 아이디 }
```

## 테스트

```bash
# packages/forms 에서
npm test
```

- `backend.test.mjs`: Apps Script를 가짜 시트 위에서 실행 (토큰 확인, 기간, 검사, 수식 차단, 재전송)
- `site.test.mjs`: 페이지를 jsdom에서 실행 (데모 모드 작성·제출, 모집 기간 밖 화면, 이스케이프, 데모 질문 = `Config.gs`, 가짜 서버·가짜 구글 로그인으로 조회·서버 검사 오류·제출·수정)

## 개인정보

신청서에는 이름·연락처 같은 개인정보가 들어갑니다. 시트는 운영진에게만 공유하고, 대회가 끝나면 안내한 대로 지우세요.
